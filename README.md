# ملتقى المسك القرآني

نظام ويب متكامل (عربي RTL) لإدارة الحلقات القرآنية: مسؤول إداري، مشرفون (ذكور / إناث / كيدز)، طلاب، تسميع، امتحانات سور، تقويم، وتقارير.

| الطبقة | التقنية |
|---|---|
| الواجهة | React 18 + Vite + React Router + FullCalendar |
| الخادم | Node.js 20+ و Express 5 |
| قاعدة البيانات | Supabase (PostgreSQL) |
| النشر | Render — خدمة واحدة تخدم الـ API والواجهة معًا |

---

## 1) ما الذي يتضمنه النظام

### المسؤول الإداري (حساب واحد ثابت)
- **المشرفون:** إضافة (يُولَّد اسم المستخدم وكلمة المرور تلقائيًا ويظهران في صفحة المشرف)، تعديل، **فصل** (يُحفظ في «سجل المفصولين» ويمكن إرجاعه)، **حذف نهائي** مع تحذير وكتابة اسم المشرف للتأكيد، ونقل طلابه لمشرف آخر عند الحذف. توليد كلمة مرور جديدة.
- **لوحة التحكم:** عدد الطلاب، الطلاب تحت التحذير، عدد المشرفين، نسبة الالتزام الشهرية، صفحات وامتحانات الشهر، مخطط آخر 14 يومًا، المواعيد القادمة، أداء المشرفين، آخر النشاطات.
- **الطلاب:** جدول مع بحث (يتجاهل الهمزات والتشكيل) وفلاتر. عند فتح الطالب: اسم مشرفه، **عدد التسميعات المحددة / التزم فيها / لم يلتزم**، جدول **امتحانات السور** (العلامة + التاريخ + ناجح/راسب)، سجل التسميع، التحذيرات.
- **التقويم:** كل مواعيد كل المشرفين (عرض) مع فلتر بالمشرف.
- **التقارير:** التقرير الشهري للمشرف (مطابق للتقرير الورقي — طباعة/PDF وتصدير Excel)، الطلاب تحت التحذير، امتحانات السور، أداء المشرفين.
- **سجل النشاط** لكل ما يحدث في النظام، و**الإعدادات**، و**الملف الشخصي** (تعديل المعلومات وكلمة المرور).

### المشرف (ذكور / إناث / كيدز)
- الواجهة تتكيّف مع النوع: «الطلاب» / «الطالبات» / «الأطفال»، ولون مختلف لكل نوع، وجنس الطالب يُحدَّد تلقائيًا (والكيدز يختار).
- إضافة وتعديل وفصل وحذف وإرجاع الطلاب بنفس آلية المسؤول.
- جدول طلابه، وعند فتح الطالب: **حجز تسميع / حجز امتحان سورة / تسجيل تسميع سابق / تحذير**.
- **التقويم:** نافذة منبثقة للحجز (بالضغط على يوم أو ساعة)، سحب الموعد لإعادة جدولته، تعديل، إلغاء، حذف.
- **تسجيل النتيجة:** «تم» (يرتفع عدّاد الطالب بالصفحات)، «لم يلتزم»، وللامتحان تُسجَّل العلامة في سجل الطالب.

### حماية الأوقات (التوقيت)
- لا يمكن حجز موعدين متداخلين لنفس المشرف أو لنفس الطالب — يُفحص في الخادم **وفي قاعدة البيانات** (قيد `EXCLUDE`) فلا يحدث تعارض حتى مع طلبين متزامنين.
- لا حجز في وقت مضى، ولا خارج ساعات الدوام (قابلة للتعديل من الإعدادات)، والموعد يجب أن ينتهي في نفس اليوم.
- لا يمكن تسجيل «تم/لم يلتزم» قبل حلول وقت الموعد.
- كل الأوقات تُحفظ UTC وتُعرض/تُفحص بمنطقة `Asia/Hebron` (قابلة للتغيير عبر `APP_TIMEZONE`).

### «تحت التحذير» (تلقائي + يدوي)
يصبح الطالب تحت التحذير إذا: عدم التزام ≥ 2 خلال 30 يومًا، أو لم يسمّع منذ 14 يومًا، أو وُضع عليه تحذير يدوي. الأرقام قابلة للتعديل من **الإعدادات**.

### إضافات لم تطلبيها (لتماسك النظام)
سجل نشاط كامل • إعدادات النظام • تحذيرات يدوية • نقل طالب بين المشرفين • تسجيل تسميع سابق • تصدير CSV/Excel وطباعة • معدّل محاولات دخول محدود (حماية من التخمين) • حماية الجلسات بكوكي `HttpOnly` • إيقاف المشرف المفصول فورًا حتى لو كان داخل النظام • واجهة متجاوبة للجوال.

## 2) التشغيل محليًا في IntelliJ IDEA

**المتطلبات:** Node.js 20 أو أحدث، وحساب Supabase.

1. افتح **مجلد المشروع الرئيسي** `masak-quran-forum` في IntelliJ (`File → Open`).
2. جهّز قاعدة البيانات (الخطوة 3 أدناه) واحصل على `DATABASE_URL`.
3. أنشئ ملف `server/.env` بنسخ `.env.example` وعبّئ القيم (`DATABASE_URL`, `JWT_SECRET`, `CREDENTIALS_KEY`, `ADMIN_PASSWORD`).
4. افتح **Terminal** داخل IntelliJ (تبويبان):

```bash
# التبويب 1 — الخادم (المنفذ 4000)
cd server
npm install
npm run migrate      # مرة واحدة: ينشئ الجداول في Supabase
npm run dev
```

```bash
# التبويب 2 — الواجهة (المنفذ 5173)
cd client
npm install
npm run dev
```

5. افتح **http://localhost:5173** وسجّل دخولك بحساب المسؤول: `ADMIN_USERNAME` / `ADMIN_PASSWORD`.

> في IntelliJ Ultimate يمكنك أيضًا إنشاء Run Configuration من نوع **npm** لكل من `server → dev` و`client → dev`.
> التوليد السريع لمفتاح سري: `node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"`

## 3) إعداد Supabase

1. أنشئ مشروعًا جديدًا في [supabase.com](https://supabase.com) واحفظ **كلمة مرور قاعدة البيانات**.
2. اضغط زر **Connect** أعلى الصفحة ← **Session pooler** وانسخ رابط الاتصال:
   `postgresql://postgres.xxxx:[YOUR-PASSWORD]@aws-0-….pooler.supabase.com:5432/postgres`
   - **استخدم Session pooler وليس Direct connection**: الاتصال المباشر يعمل على IPv6 فقط وRender لا يدعمه.
   - إن احتوت كلمة المرور رموزًا خاصة (`@ # / : %`) فحوّلها بترميز URL (مثال `@` ← `%40`) أو اختر كلمة مرور من حروف وأرقام.
3. ضع الرابط في `DATABASE_URL`.
4. أنشئ الجداول بأحد طريقين:
   - `npm run migrate` من مجلد `server` (الأسهل)، **أو**
   - انسخ محتوى `database/schema.sql` إلى Supabase ← **SQL Editor** ← Run.
   (الملف آمن لإعادة التشغيل أكثر من مرة.)

الجداول تُنشأ مع **RLS مفعّل بلا سياسات**، أي أن مفتاح `anon` العام في Supabase لا يستطيع قراءة أي شيء؛ الخادم وحده يصل للبيانات. **لا تضع أي مفاتيح Supabase في الواجهة.**

## 4) النشر على Render

1. ارفع المشروع إلى **GitHub** (ملف `.gitignore` جاهز ويستثني `.env` و`node_modules`).
2. في Render: **New → Blueprint** واختر المستودع (يقرأ `render.yaml` تلقائيًا)، **أو** **New → Web Service** يدويًا بهذه الإعدادات:

| الحقل | القيمة |
|---|---|
| Runtime | Node |
| Build Command | `npm run render-build` |
| Start Command | `npm start` |
| Health Check Path | `/api/health` |

3. أضف متغيرات البيئة (Environment):

| المتغير | القيمة |
|---|---|
| `NODE_ENV` | `production` |
| `NODE_VERSION` | `22` |
| `DATABASE_URL` | رابط Session pooler من Supabase |
| `JWT_SECRET` | نص عشوائي 48+ حرفًا (Blueprint يولّده تلقائيًا) |
| `CREDENTIALS_KEY` | نص عشوائي (Blueprint يولّده تلقائيًا) — **لا تغيّره لاحقًا** |
| `ADMIN_USERNAME` | مثال `admin` |
| `ADMIN_PASSWORD` | كلمة مرور قوية للمسؤول |
| `APP_TIMEZONE` | `Asia/Hebron` |

4. اضغط Deploy. أمر البناء يثبّت الحزم ويبني الواجهة وينفّذ الـ migration على Supabase تلقائيًا، ثم يُنشئ الخادم حساب المسؤول عند أول تشغيل.

**ملاحظات:**
- الخطة المجانية في Render تدخل في «سبات» بعد 15 دقيقة من عدم الاستخدام وأول فتح بعدها يستغرق ~30–60 ثانية. للاستخدام الفعلي يُنصح بخطة مدفوعة.
- نسيتِ كلمة مرور المسؤول؟ ضعي كلمة جديدة في `ADMIN_PASSWORD` مع `ADMIN_FORCE_RESET=true`، أعيدي النشر، ثم احذفي `ADMIN_FORCE_RESET`.

## 6) هيكل المشروع

```
masak-quran-forum/
├─ database/schema.sql          مخطط قاعدة البيانات (Supabase)
├─ server/                      Express API
│  └─ src/
│     ├─ index.js               نقطة التشغيل + خدمة الواجهة في الإنتاج
│     ├─ routes/                auth, supervisors, students, appointments, dashboard, reports, ...
│     ├─ services/              إحصائيات الطلاب، الأداء، الإعدادات، سجل النشاط
│     └─ middleware/ utils/     الجلسات، الأخطاء، التحقق، التشفير، المناطق الزمنية
├─ client/                      React (Vite)
│  └─ src/pages, components, lib, context
├─ render.yaml                  إعداد Render
└─ .env.example                 متغيرات البيئة
```

## 7) الأمان — باختصار
- كلمات المرور مخزّنة بـ **bcrypt** للتحقق، وبنسخة **مشفّرة AES-256-GCM** فقط لتمكين المسؤول من عرض بيانات دخول المشرف. إذا غيّر المشرف كلمته بنفسه تُحذف النسخة المشفّرة ولا تعود ظاهرة للمسؤول.
- جلسات JWT في كوكي `HttpOnly` + `SameSite=Lax` (+ `Secure` في الإنتاج)، مدتها 7 أيام.
- المشرف لا يرى ولا يعدّل إلا طلابه ومواعيده (يُفحص في الخادم في كل طلب).
- رؤوس أمان (Helmet/CSP)، وتحقق صارم من المدخلات (Zod)، واستعلامات مهيّأة (لا SQL injection).
